# PvP Quiz

Асинхронная квиз-дуэль один на один. Игрок проходит раунд из 5 вопросов, получает ссылку
и отправляет её знакомому в мессенджер. Тот открывает ссылку в браузере, играет те же
вопросы — и оба видят результат.

Это учебный проект. Главная цель — научиться писать сервисы на Java 25 без Spring и освоить
новые конструкции языка. Игра — полигон с реалистичными требованиями: конкурентные запросы,
античит, стейт-машина матча.

## Принципы

- **Чистый JDK 25, без фреймворков.** Всё, что в Spring-проекте дал бы фреймворк, пишем сами —
  и разбираемся, что именно он делал за нас.
- **Короткий список зависимостей:** PostgreSQL JDBC, HikariCP, Flyway, в тестах — JUnit 5 и
  Testcontainers. Каждая добавляется вместе с первым классом, которому она нужна. Для web push
  решим, когда дойдём: библиотека или своё шифрование на KDF API из JDK.
- **HTTP — `com.sun.net.httpserver.HttpServer` из JDK**, каждый запрос — в своём виртуальном
  потоке. Обычный блокирующий код, без реактивщины.
- **Класс за классом.** Класс появляется, когда без него становится неудобно.

## Требования

- JDK 25
- Maven 3.9+

## Запуск

```bash
mvn -q compile && java -cp target/classes kz.pvpquiz.Main
```

Проверка:

```bash
curl -i localhost:8080/health
```

Ответ — `200` и `{"status":"ok"}`, на любой другой путь — `404`.

## Остановка

Сервер останавливается мягко: сразу перестаёт принимать соединения и даёт текущим запросам
до 2 секунд, чтобы завершиться.

- В терминале — `Control+C`.
- Из IDEA — кнопка Stop (`Cmd+F2`). `Control+C` в окне Run не работает: это не терминал.
- Если не помните, где запущен:

  ```bash
  kill $(lsof -ti tcp:8080 -sTCP:LISTEN)
  ```

`kill -9` — только если процесс не отвечает: при нём мягкая остановка не выполнится.

## Структура

```
src/main/java/kz/pvpquiz/
├── Main.java        точка входа; позже — ручная сборка зависимостей вместо DI-контейнера
├── platform/        то, что давал Spring; про игру не знает ничего
│   ├── http/        сервер, Request/Response, Router; filter/ — сквозная обработка запросов
│   ├── config/      конфигурация из переменных окружения
│   ├── context/     контекст запроса на ScopedValue
│   ├── json/        парсер и сериализатор
│   ├── db/          пул соединений, транзакции, маппинг строк в record
│   ├── jobs/        планировщик и очередь задач в Postgres
│   ├── template/    шаблонизатор HTML
│   └── security/    подпись токенов
└── game/            предметная область, разложена по фичам
    ├── player/      анонимный игрок, ник
    ├── content/     вопросы, категории, импорт, модерация
    ├── match/       матч, стейт-машина, античит
    ├── share/       ссылка на матч, превью для мессенджеров
    ├── push/        web push
    └── metrics/     события и отчёт по воронке
```

Зависимости идут только в одну сторону: `game` → `platform`, никогда наоборот.

## План

1. `Main` — `HttpServer` на виртуальных потоках, `GET /health`, мягкая остановка
2. `Request` / `Response` — обработчик как функция от запроса к ответу
3. `Router` — шаблоны путей с параметрами, ответы 404 и 405
4. `AppConfig` и `Database` — конфигурация из окружения, `db.inTransaction(tx -> …)`
5. Матч — sealed-состояния, вопросы по одному, приём ответа, античит
6. Дальше: фильтры, контент и модерация, фронтенд, превью ссылок, push, метрики

Что уже сделано, какие выводы по каждому шагу и что делаем сейчас — в
[docs/progress.md](docs/progress.md).

## Что делал Spring и что пишем мы

| В Spring | У нас | Что из Java |
|---|---|---|
| Spring Boot + встроенный Tomcat | `Main` на `HttpServer` | виртуальные потоки, `void main()`, `import module` |
| `@RestController`, `@PathVariable` | `Request`, `Response`, `Router` | records, pattern matching в `switch` |
| `RequestContextHolder`, MDC | контекст запроса | `ScopedValue` |
| `@ControllerAdvice` | ошибки как sealed-результаты | sealed-интерфейсы, record patterns |
| `@ConfigurationProperties` | `AppConfig` | records, код до `super()` в конструкторе |
| Jackson | свой JSON | sealed-дерево, исчерпывающий `switch` |
| DI-контейнер | ручная сборка в `Main` | — |
| `@Transactional`, `JdbcTemplate` | `db.inTransaction(tx -> …)` | лямбды, text blocks |
| `@Scheduled` | планировщик и очередь в Postgres | виртуальные потоки |
| Thymeleaf | свой шаблонизатор | sealed-узлы, pattern matching |
