# PvP Quiz — инструкции для Claude

Учебный проект. Цель — научиться писать сервисы на Java 25 без Spring и освоить новые
конструкции языка. Игра (асинхронная квиз-дуэль один на один) — полигон, а не самоцель.
О продукте и план шагов — в README.md.

Текущее состояние, следующая задача и выводы по пройденным шагам:

@docs/progress.md

## Как мы работаем

- Код пишет пользователь, сам, класс за классом, чтобы понимать, зачем каждая вещь.
- На каждый класс Claude ставит задачу: какое неудобство класс убирает и что в Spring делалось
  за нас, какие решения внутри, где грабли, как проверить. Сигнатуры и подсказки — можно,
  готовую реализацию — только по просьбе.
- На «готово» или «проверь» — прочитать код и сделать ревью с объяснением «почему».
- Файлы проекта не создавать и не править без явной просьбы. Обвязку окружения
  (.gitignore и т. п.) — предлагать.
- Утверждения о поведении JDK, Maven и инструментов проверять экспериментом в scratchpad,
  а не по памяти.
- В экспериментах не трогать процессы пользователя: копия на свободном порту (не 8080),
  останавливать только процессы, которые запустил сам, по их PID. Никаких `pkill -f`
  и `lsof -ti` по общим признакам — однажды так был остановлен сервер пользователя.
- Порядок — вертикальный срез: класс появляется, когда без него становится неудобно.
  Глубина в ядре платформы законна — это и есть урок. Предупреждать только о тупиках,
  которые ничему не учат: свой HTTP/2, свой пул соединений вместо Hikari и т. п.
- К каждому шагу привязывать конструкции современной Java там, где они решают реальную
  задачу, и сравнивать с тем, как это делал Spring.
- «фиксируем» — обновить docs/progress.md: сделанный шаг, выводы, следующая задача,
  открытые решения. Коммитит пользователь.
- «продолжаем» — сказать, где остановились, и поставить следующую задачу.

## Стек и ограничения

- JDK 25, Maven, один модуль. Preview-возможности (StructuredTaskScope, StableValue) —
  только в отдельных экспериментах, не в коде сервиса.
- Без фреймворков и тяжёлой инфраструктуры: никаких Spring, Quarkus, Micronaut, Javalin,
  Jetty, Netty, ORM, Kafka, Redis, MongoDB, Kubernetes, микросервисов.
- Разрешённые зависимости: PostgreSQL JDBC, HikariCP, Flyway; в тестах — JUnit 5 и
  Testcontainers. Каждая добавляется вместе с первым классом, которому она нужна.
- HTTP — `com.sun.net.httpserver.HttpServer` с `Executors.newVirtualThreadPerTaskExecutor()`,
  блокирующий JDBC, без реактивщины.

## Соглашения

- Пакет `kz.pvpquiz`. `platform/` — то, что давал фреймворк; `game/` — предметная область,
  разложенная по фичам. Зависимости только в одну сторону: `game` → `platform`.
- Запуск: `mvn -q compile && java -cp target/classes kz.pvpquiz.Main`,
  проверка: `curl -i localhost:8080/health`.
- Общение на русском.
